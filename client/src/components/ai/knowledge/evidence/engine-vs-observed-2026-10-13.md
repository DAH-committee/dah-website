# 우리 수식 엔진 대 구글 관찰값 (스냅샷)

실행: 2026-10-13 00시대(KST), `node client/scripts/observe/run-corpus.mjs`. 엔진(SE 담당)이 작업 중인 상태의 파일을 그대로 읽었으므로 숫자는 이후 바뀐다. 이 파일은 "무엇이 어긋나 있었나"의 기록이다. 비교는 구글 CSV 표시값과 엔진 표시 문자열의 정확한 일치다.
결과: 일치 495 / 불일치 148 / 전체 643. (하네스의 첫 실행은 행 한도 버그로 173/643 이었고 고친 뒤 값이다.)

불일치 묶음(대표만, 전체는 스크립트 출력으로 확인)
1. 빈 칸 처리(하네스는 격자 안 빈 칸을 ''로 돌려줌): `A7+1` 기대 1 실제 #VALUE!, `A7&"x"` 기대 x 실제 nullx, `A7=0`, `A7=""` FALSE, `ISBLANK(A7)` FALSE, `LEN(A7)` 4, `TYPE(A7)` 2, `IF(A7,1,2)` #VALUE!. 엔진이 ''를 진짜 빈 칸으로 취급하지 못하는 것으로 보인다(구글: 빈 칸은 0 이자 "" 이고 ISBLANK TRUE).
2. 빈 문자열 수식(="")과 빈 칸의 구분: `COUNTA(A1:A12)` 기대 11 실제 12, `COUNTBLANK` 기대 2 실제 1, `COUNTIF(범위,"")` 기대 2 실제 1, `COUNTIFS(...,"")`, `COUNTUNIQUE` 기대 10 실제 11. 구글에서 COUNTA 는 ="" 도 센다(관찰 11 = 12칸 - 진짜 빈 칸 1).
3. 표시 자릿수: 구글 일반 서식은 유효숫자 약 10자리(0.3333333333, 1E+15, 1.23457E+17)이고 엔진은 12자리(0.333333333333)이거나 정수를 그대로 표시(1000000000000000). 같은 표시 규칙이 필요하다.
4. 로캘: 구글(ko-KR)의 `TEXT(날짜,"dddd")` 는 월요일, `mmmm` 은 1월, `AM/PM` 은 오후인데 엔진은 영어(Monday, January, PM). `DATE(2024,13,1)` 의 자동 표시는 구글 "2025. 1. 1", 엔진 "2025-01-01". 의도된 차이면 corpus 의 localeDependent 항목으로 분리한다.
5. 날짜 함수: `DATEVALUE("2024-02-29")` 기대 45351(숫자), 실제 날짜 문자열 표시. `DATEVALUE("2/29/2024")` 구글은 ko-KR 에서 #VALUE!, 엔진은 해석. `DATEVALUE("2024. 2. 29")` 구글 45351, 엔진 #VALUE!. `TIMEVALUE("13:30")` 구글 0.5625, 엔진 "13:30:00". `WORKDAY` 가 날짜 서식 함수에 감싸지면 #VALUE!. `DATEDIF(…,"YD")` 167 대 166. `YEARFRAC` 기준 1 에서 값이 다름(1.454794521 대 1.45620437956).
6. 거듭제곱: `0^0` 기대 1 실제 #NUM!, `(-8)^(1/3)` 와 `POWER(-8,1/3)` 기대 -2(실수 세제곱근) 실제 #NUM!. `0.1+0.2=0.3` 기대 TRUE(비교 허용오차), 실제 FALSE. `SQRT(2)*SQRT(2)=2` 도 TRUE 기대. `0.1+0.2-0.3` 기대 0, 실제 5.55E-17.
7. 오류 종류: `INDEX` 범위 밖 기대 #NUM!(관찰, 재확인 항목) 실제 #REF!, `CHOOSE(5,1,2)`, `MID("abc",0,1)` 기대 #NUM! 실제 #VALUE!, `VLOOKUP` 열 초과 기대 #REF! 실제 #VALUE!.
8. TEXT 서식: `TEXT(12,"@")` 21(뒤집힘), `TEXT(0.5,"# ?/?")`, `TEXT(D1,"aaa")` 가 요일 약자(구글은 서식이 아니라 글자 그대로), `TEXT(D1,"e")`, `"q"`, `TEXT(0.1+0.2,"0.00000000000000000")`(구글은 15자리 이후를 0 으로 채움).
9. 구현이 없는 함수(#NAME?): TO_PERCENT, CEILING.MATH, FLOOR.MATH, BASE, PERCENTRANK, OFFSET/INDIRECT(빈 문자열), 그 밖에 corpus 에 쓴 일부.
10. QUERY 12건, SORT 8건, FILTER 5건, TEXTJOIN/JOIN, REGEXMATCH/REGEXREPLACE, ARRAYFORMULA 일부가 불일치. 상세는 스크립트 출력(`--only gs-5`처럼 접두어로 좁힘).

주의: "의심 항목"(evidence/sheets-observed-findings.md 마지막 절)은 구글 쪽 관찰이 의심스러운 것이라 엔진이 달라도 먼저 재관찰한다.
