# 구글 폼 관찰 (질문 유형, 설정, 공개 데이터 구조)

관찰일 2026-10-12. 내 계정의 스크래치 폼 "[테스트] AI 관찰 설문"(파일 이름은 "제목 없는 설문지")을 만들어 질문 유형을 하나씩 추가하고 게시한 뒤, 응답자용 `viewform` 페이지의 `FB_PUBLIC_LOAD_DATA_`(구글이 응답자 화면에 싣는 구조 데이터)를 같은 로그인 탭에서 한 번 받아 읽었다. 구글 스크립트를 해독하거나 내부 API 를 부르지 않았고, 쓴 것은 페이지가 스스로 싣는 데이터뿐이다. 게시하지 않은 폼의 viewform 은 HTTP 403 이었다(관찰). 스크래치 폼은 관찰 후 휴지통으로 옮겼다.

## 질문 유형 메뉴 (화면 관찰)

유형 선택 목록 순서(구분선 단위): 단답형, 장문형 / 객관식 질문, 체크박스, 드롭다운 / 파일 업로드 / 선형 배율, 등급, 객관식 그리드, 체크박스 그리드 / 날짜, 시간. 총 11종. 순위(랭킹) 유형은 이 목록에 없었다.
- 파일 업로드를 고르면 확인 창이 뜬다: 파일은 설문지 소유자의 Drive 에 올라가고, 응답자는 Google 로그인이 필요하며, 신뢰하는 사람에게만 공유해야 한다는 안내(취소하면 유형이 바뀌지 않았다).
- 새 질문의 기본 유형은 객관식(옵션 1 하나, "필수" 끔).

## viewform 데이터의 질문 유형 번호 (관찰)

`FB_PUBLIC_LOAD_DATA_[1][1]` 이 항목 배열이다. 항목 = `[항목id, 제목, 설명, 유형번호, [질문 상세...], ...]`. 질문 상세 = `[질문id, 보기들, 필수(0/1), ...]`.
관찰된 유형 번호(화면 이름 -> 번호):
- 단답형 -> 0, 장문형 -> 1, 객관식 -> 2, 드롭다운 -> 3, 체크박스 -> 4, 선형 배율 -> 5
- 객관식 그리드 -> 7, 체크박스 그리드 -> 7 (같은 번호, 상세의 끝 쪽 플래그가 `[0]` 이면 객관식 그리드, `[1]` 이면 체크박스 그리드)
- 날짜 -> 9, 시간 -> 10, 등급 -> 18
- 보기: 객관식/체크박스/드롭다운은 `[["옵션 1"]]` 꼴(보기 문자열이 첫 칸). 객관식 질문에 보기를 직접 입력한 경우 `["보기A",null,null,null,0]`.
- 선형 배율: 보기 목록이 `[["1"],["2"],...,["5"]]`, 양끝 라벨은 상세의 4번째 칸 `["",""]`.
- 그리드: 열 보기는 `[["1 열"]]`, 행 이름은 상세의 4번째 칸 `["행1"]`.
- 날짜(상세 8번째 칸 `[0,1]`)와 시간(상세 7번째 칸 `[0]`)의 마지막 배열은 연도 포함/시간 또는 기간 같은 옵션 플래그로 보이지만 의미는 미확인.
- 미확인: 파일 업로드 유형 번호(확인 창에서 취소해 관찰하지 못함), 섹션 구분 번호, 제목/설명 항목 번호, 이미지/동영상 항목 번호, 퀴즈 점수·정답·피드백이 실리는 위치, 필수 질문과 검증 규칙의 위치. 가져오기(import) 기능을 만든다면 이 항목들은 같은 방법으로 별도 폼을 만들어 추가 관찰한다.
- 최상위: `[1][8]` 이 설문지 제목, `[1][0]` 이 설명(관찰에서는 null). 그 밖의 칸 의미는 미확인.

## 공개 도움말에서 확인한 규칙 (출처 URL)

질문 유형: https://support.google.com/docs/answer/7322334 (2026-10-12 WebFetch)
- 단답형: 규칙으로 글자 수 상한 등. 장문형: 글자 수 상한/하한.
- 객관식/체크박스: "기타" 옵션 포함 가능(응답자가 짧게 입력). 객관식, 체크박스, 드롭다운은 응답에 따라 섹션 이동(분기) 가능.
- 파일 업로드: 공유 드라이브에 저장된 폼이나 DLP 가 켜진 관리자 환경에서는 쓸 수 없고, 응답자는 Google 로그인이 필요하며, 소유자 Drive 의 새 폴더에 저장됨. 파일 형식, 최대 파일 수, 최대 크기를 정할 수 있음.
- 선형 배율: 0 또는 1 에서 시작, 2~10 의 정수에서 끝, 양끝 라벨. 등급: 별/하트/엄지 아이콘, 3~10 의 정수.
- 그리드: 행과 열 보기를 둔다. "열마다 응답 하나로 제한" 규칙 가능.
- 날짜는 mm/dd/yyyy 형식(연도/시간 포함 옵션), 시간은 hh:mm AM/PM 또는 기간(시 분 초).

응답 검증: https://support.google.com/docs/answer/3378864 (2026-10-12 WebFetch)
- 단답형: 숫자(이상, 이하, 사이, 같음 등), 텍스트(포함, 이메일 형식 등), 길이(최대/최소 글자 수), 정규식(포함, 포함 안 함, 일치, 불일치).
- 장문형: 길이, 정규식.
- 체크박스: 최소 N개, 최대 N개, 정확히 N개.
- 그리드: "각 행에 응답 필요", "열마다 응답 하나로 제한", "행 순서 섞기".
- 모든 규칙에 사용자 지정 오류 문구를 넣을 수 있다. 정규식 예: 10자리 전화번호 `[0-9]{10}` 일치.

퀴즈: https://support.google.com/docs/answer/7032287 (2026-10-12 검색 결과 발췌)
- 설정에서 "퀴즈로 만들기"를 켠다. 질문마다 정답, 점수, 자동 피드백.
- 성적 공개: 기본은 제출 직후 즉시. "수동 검토 후 나중에"를 고를 수 있고, 이메일을 수집하면 응답별 점수를 수동 입력하고 "점수 공개"로 메일 발송.
- 요약: 자주 틀린 문제, 정답이 표시된 그래프, 평균·중앙값·범위.
- Forms API 문서(https://developers.google.com/workspace/forms/api/guides/setup-grading, 2026-09-03 갱신): 체크박스, 객관식, 드롭다운과 단답형만 정답 자동 채점. 단답형은 정답과 정확히 일치해야 하고, 단답형에는 일반 피드백만(맞음/틀림 피드백 없음). 그 밖의 유형은 수동 채점과 일반 피드백만.

한도(공식 도움말 직접 확인 못 함, 커뮤니티 제품 전문가 글 인용: https://support.google.com/docs/thread/363061480):
- 질문 전체에서 보기 합 2000개, 섹션 75개, 콘텐츠(질문, 설명, 이미지, 동영상) 300개 이하, 응답 하나의 전체 글자 수 약 32000자. 공식 확인은 미확인.

## 우리 폼 편집기(FM)가 따를 설계 규칙

관찰과 도움말에서 뽑은 규칙. 우리 코드의 한도(`formLogic.js` LIMITS: fields 300, options 200, sections 75, rows 50, columns 20)와 비교해 어긋나는 곳만 적는다.
1. 구글에는 순위(랭킹) 유형이 없다. 우리 유형 목록에는 phone, email, studentid 처럼 구글에 없는 "특수 단답형"이 있다(구글은 단답형 + 검증 규칙으로 처리). 구글 폼 가져오기를 만들면 이 셋은 단답형 + 정규식/이메일 규칙으로 바꿔 읽는 것이 자연스럽다.
2. 구글 그리드의 `객관식`/`체크박스` 는 같은 유형 번호(7) 안의 플래그 차이다. 우리는 radio_grid / checkbox_grid 로 나눠서 가진다. 가져오기 시 플래그로 구분한다.
3. 구글의 파일 업로드는 응답자 로그인이 필수다. 우리 file 유형이 로그인 없이 받는다면 다른 동작임을 안내 문구에 남긴다.
4. 구글 선형 배율은 시작 0 또는 1, 끝 2~10. 등급은 3~10. 우리 값 범위가 다르면(scale, ratingMax 3..10 은 같음) 가져오기 때 맞춘다.
5. 퀴즈 자동 채점은 선택형 3종(객관식, 체크박스, 드롭다운)과 단답형 정답 일치까지만이다. 장문형/날짜/시간/그리드 채점은 구글도 수동이다. 우리 quiz 가 그리드나 장문형에 정답을 허용하면 구글과 다르다.
6. 분기는 객관식, 체크박스(구글 표기상), 드롭다운에서 섹션 이동으로 한다. 우리 logic 은 radio/select 와 section.after 에만 있고 "뒤로만" 이동하는 제약을 둔다(구글은 앞 섹션으로도 이동 가능한지 이 조사에서 미확인).
