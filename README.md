# 한림대학교 디지털인문예술전공 웹사이트

한림대학교 디지털인문예술전공(DAH)의 공식 웹사이트를 관리하는 저장소입니다. 전공을 처음 찾는 예비 학생과 재학생에게는 전공의 정보와 활동을 안내하고, 교수님·운영위원회·향후 인수인계받는 학생 관리자에게는 콘텐츠를 지속해서 운영할 수 있는 기반을 제공합니다.

사이트 주소: [dah-hallym.vercel.app](https://dah-hallym.vercel.app)

## 이 사이트가 하는 일

- 전공 소개, 연혁, 교수진·멘토, CI를 안내합니다.
- 교육과정, 교과목, 코드쉐어링, 나노디그리 등 학사 정보를 제공합니다.
- 공지사항과 자료실을 통해 학사·행사 정보를 전달합니다.
- 프로젝트 전시회, 공모전, 특강, 동아리, 학생 성과, 쇼케이스, 포트폴리오, 취업 현황을 아카이브합니다.
- 전시 접수와 행사 신청을 온라인으로 받고, 관리자는 결과와 콘텐츠를 한곳에서 관리합니다.
- 한국어·영어 화면을 지원합니다. 영문 원고가 등록된 콘텐츠는 영어 화면에서 함께 제공합니다.

## 누가 어떻게 사용하나요?

| 사용자 | 주로 하는 일 |
| --- | --- |
| 방문자·예비 학생 | 전공·교육과정·활동·공지 확인 |
| 재학생 | 전시·공모전·특강·자료실 확인, 전시 및 행사 접수 |
| 교수님 | 공개된 전공·학사·학생 활동 정보 확인 및 관리자에게 수정 요청 |
| 관리자·운영위원회 | 로그인 후 각 페이지의 `편집` 또는 관리자 대시보드에서 콘텐츠 관리 |
| 향후 인수인계자 | 이 문서와 관리자 화면을 기준으로 운영 환경과 배포 흐름 파악 |

## 운영 원칙

1. **콘텐츠는 관리자 화면에서 관리합니다.** 공지, 전시, 공모전, 특강 등 일상적인 내용 수정은 코드를 고치지 않아도 됩니다.
2. **코드는 변경 전 최신 상태를 먼저 받습니다.** 여러 사람이 동시에 작업하므로 작업 시작 전 `git pull`을 권장합니다.
3. **비밀값은 저장소에 올리지 않습니다.** 데이터베이스 주소, 로그인 비밀키, 파일 저장소 토큰, 메일·Google 설정값은 환경변수 관리 화면에만 보관합니다.
4. **운영 사이트를 먼저 보호합니다.** 큰 화면 개편이나 기능 변경은 로컬 또는 미리보기 배포에서 확인한 뒤 운영 배포로 반영합니다.

## 저장소 구조

```text
client/                 공개 웹사이트와 관리자 대시보드
  src/pages/            각 공개·관리자 페이지
  src/components/       공통 UI, 레이아웃, 편집 도구
  src/data/             기본 안내 문구와 정적 데이터
  public/               파비콘, 로고, robots.txt, sitemap.xml 등 공개 파일

server/                 API 서버
  src/                  인증, 권한, DB 연결, 콘텐츠·업로드 API
  scripts/              데이터 마이그레이션·초기화 보조 도구
  test/                 서버 기본 동작 확인
```

`docs/`는 개인 작업 메모·운영 자료를 로컬에서만 보관하는 폴더입니다. 학교 공용 저장소에는 사이트 운영에 필요한 코드와 이 README만 유지합니다.

## 관리자 화면 사용 안내

1. 사이트 우측 상단의 설정 아이콘에서 관리자 로그인을 합니다.
2. 각 공개 페이지의 `편집` 버튼 또는 관리자 대시보드의 메뉴를 엽니다.
3. 수정 후 저장하면 공개 상태 설정에 따라 사이트에 반영됩니다.
4. 전시·공모전·특강처럼 날짜가 있는 콘텐츠는 새 항목으로 남겨 아카이브가 이어지도록 관리합니다.

관리자 계정은 사전에 데이터베이스에 등록된 이메일만 로그인할 수 있습니다. 등록되지 않은 이메일은 새 사용자로 생성되지 않으며 접근이 거부됩니다.

## 로컬에서 실행하기

Node.js의 현재 LTS 버전을 권장합니다. 처음 한 번만 각 폴더에서 패키지를 설치합니다.

```bash
# 1. 프론트엔드
cd client
npm install
npm run dev

# 2. 별도 터미널에서 API 서버
cd server
npm install
npm run dev
```

프론트엔드는 보통 `http://localhost:5173`, API 서버는 `http://localhost:4000`에서 실행됩니다. 실제 데이터베이스나 업로드 기능을 시험하려면 별도의 로컬 환경변수가 필요합니다. 비밀값은 동료에게 메시지나 저장소 파일로 공유하지 말고, 담당자가 안전한 환경변수 관리 화면에서 설정합니다.

## 배포와 환경변수

프론트엔드는 Vercel, API 서버는 Render에서 각각 배포합니다. 코드가 기본 브랜치에 반영되면 연결된 배포 서비스가 새 버전을 만들 수 있습니다.

프론트엔드에서 주로 확인하는 값은 다음과 같습니다.

| 이름 | 의미 |
| --- | --- |
| `VITE_API_URL` | Render API 서버 주소 |
| `VITE_SITE_URL` | 공개 사이트의 대표 주소 |
| `VITE_GA_ID` | Google Analytics 측정 ID. 비어 있어도 사이트 기능에는 영향 없음 |

백엔드의 `DATABASE_URL`, `JWT_SECRET`, `BLOB_READ_WRITE_TOKEN`, 메일·Google OAuth 관련 값은 **프론트엔드 Vercel에 넣지 않습니다.** Render의 서버 환경변수에만 둡니다.

### 행사 파일을 Google Drive에 저장하려면

전시회 원본, 공모전 제출물, 행사 신청 첨부파일을 **파일 질문 단위로** 다른 저장소에 보냅니다. 코드를 고치지 않고 관리자 화면에서만 설정합니다.

| 무엇을 받는가 | 저장 위치 | 처리 방식 |
| --- | --- | --- |
| 웹 전시용 이미지 | Vercel Blob | 최장변 2400px, WebP로 변환해 사이트에 바로 사용 |
| 인쇄용·원본 파일 | Google Drive | **변환하지 않음.** 원본 바이트·확장자·MIME·파일명 보존 |
| 일반 제출 서류 | Blob 또는 Drive | 변환하지 않음 |

폴더는 서버가 폼 설정과 DB 값으로 조립합니다. 제출자나 브라우저가 폴더 이름을 정하지 못합니다.

```
전공 사이트 루트
└── 2026-2                        학기 또는 연도
    └── 전공 프로젝트 전시회        폼 이름
        └── 디자인씽킹             제출자가 고른 과목 (학기별 개설 과목 목록에 있는 값만)
            └── 원본               파일 질문의 마지막 폴더
```

경로 규칙은 폼 편집기의 `폴더 경로 규칙`에서 고릅니다. 이번 학기 폴더를 이미 만들어 두었다면 그 폴더를 루트로 지정하고 `과목 / 원본` 규칙을 쓰면 기존 구조를 그대로 씁니다.

#### 연결 방식은 두 가지 — 하나만 고르면 된다

| 방식 | Google Cloud 콘솔 작업 | 준비물 | 파일 크기 | 언제 쓰나 |
| --- | --- | --- | --- | --- |
| **Apps Script 릴레이** (간단) | **필요 없음** | 스크립트 배포 주소 + 비밀키 | 기본 30MB까지 | 평소 운영. 운영진이 바뀌어도 스크립트만 다시 배포하면 끝 |
| Drive API + OAuth (정식) | 필요 (1회) | OAuth 클라이언트 ID·시크릿 | 기본 100MB까지 | 아주 큰 인쇄 원본을 받아야 할 때 |

어느 쪽을 골라도 **학생이 보는 화면은 사이트의 접수 폼 그대로**입니다. Apps Script는 화면 없이 파일만 받는 뒷단 수신처로만 쓰입니다.

```
제출자 브라우저 → dah-website 서버 → (Apps Script 웹앱 또는 Drive API) → Drive 폴더
```

#### Apps Script 릴레이로 연결하기 (권장)

1. 서버 환경변수 `DRIVE_TOKEN_ENC_KEY`만 Render에 넣습니다(비밀키 암호화용, `openssl rand -base64 32`).
2. 파일을 보관할 Google 계정으로 <https://script.google.com>에서 새 프로젝트를 만듭니다.
3. 저장소의 `server/scripts/apps-script/drive-relay.gs` 내용을 전부 붙여 넣고, 맨 위 `SHARED_SECRET`을 임의의 32자 이상 문자열로 바꿉니다. **이 값을 GitHub에 올리지 않습니다.**
4. `배포 → 새 배포 → 웹 앱`으로 배포합니다. `다음 사용자로 실행: 나`, `액세스 권한이 있는 사용자: 모든 사용자`로 둡니다.
5. 나온 `.../exec` 주소를 복사합니다.
6. 사이트 `관리 → 저장소 · Google Drive → Apps Script 연결 추가`에 연결 이름, 루트 폴더 URL, `/exec` 주소, 3번의 비밀키를 넣고 등록합니다. 등록하는 순간 서버가 실제로 통신해 저장 계정과 루트 폴더 접근을 확인합니다.
7. `테스트 파일 업로드`로 `_DAH_INTEGRATION_TEST` 폴더에 파일이 들어오는지 봅니다.

스크립트 코드를 고친 뒤에는 **새 배포를 만들어야** 반영됩니다. 30MB보다 큰 파일을 받아야 하면 `APPS_SCRIPT_MAX_UPLOAD_MB`를 올리거나 아래 Drive API 방식으로 바꿉니다.

#### Drive API + OAuth로 연결하기 (1회 준비, 서버 담당자)

1. Google Cloud Console에서 **Drive API를 사용 설정**하고, OAuth 동의 화면을 구성한 뒤 **웹 애플리케이션** OAuth 클라이언트를 만듭니다.
2. 승인된 리디렉션 URI에 API 서버의 콜백 주소를 **문자 단위로 같게** 등록합니다.
   - 배포: `https://<API 서버 도메인>/auth/google/drive/callback`
   - 로컬: `http://localhost:4000/auth/google/drive/callback`
3. Render 서버 환경변수에 아래 값을 넣습니다. Vercel·GitHub에는 넣지 않습니다.

| 이름 | 용도 |
| --- | --- |
| `GOOGLE_DRIVE_CLIENT_ID` | OAuth 클라이언트 ID |
| `GOOGLE_DRIVE_CLIENT_SECRET` | OAuth 클라이언트 시크릿 |
| `GOOGLE_DRIVE_REDIRECT_URI` | 위 2번에서 등록한 콜백 주소 |
| `DRIVE_TOKEN_ENC_KEY` | refresh token 암호화 키. 32바이트 랜덤값의 base64 (`openssl rand -base64 32`) |
| `GOOGLE_DRIVE_SCOPE` | (선택) 기본값 `https://www.googleapis.com/auth/drive` |
| `GOOGLE_DRIVE_MAX_UPLOAD_MB` | (선택) Drive 원본 업로드 상한. 기본 100 |
| `APPS_SCRIPT_MAX_UPLOAD_MB` | (선택) Apps Script 릴레이 업로드 상한. 기본 30 |

4. DB에 저장소 테이블을 만듭니다. 서버는 부팅할 때 이 테이블을 스스로 확인·생성하므로 **재배포만으로도 준비됩니다.** 수동으로 돌릴 때는 `server/`에서 `node scripts/migrate-phase53-drive.mjs`를 실행합니다. 기존 폼 설정은 지우지 않고, 파일 질문에 저장소 설정이 없을 때만 폼 전역 Drive 설정을 질문 단위로 복사합니다.

권한 범위에 관한 근거: Google 문서는 `drive.file`을 "앱이 만든 파일, 또는 Google Picker/앱의 파일 선택기로 사용자가 앱에 공유한 파일"만 다룰 수 있는 범위로 정의합니다. 이 사이트는 **운영진이 이미 만들어 둔 폴더의 URL을 붙여 넣어 재사용**하는 흐름이 필수라서 `drive.file`만으로는 그 폴더를 찾지 못합니다. 그래서 기본값을 `https://www.googleapis.com/auth/drive`로 둡니다. 이 범위는 Google이 분류한 restricted 범위이므로, 외부 사용자 유형으로 공개할 때는 검증 절차가 필요합니다. 학교 Workspace 계정으로 내부(Internal) 앱으로 만들면 검증 없이 사용할 수 있습니다. 나중에 Google Picker를 붙이면 `GOOGLE_DRIVE_SCOPE`를 `https://www.googleapis.com/auth/drive.file`로 바꿔 좁힐 수 있습니다.

주의: 외부 사용자 유형이고 게시 상태가 **테스트**인 OAuth 앱은 Google이 refresh token을 **7일**만 유효하게 발급합니다. 매주 다시 연결하고 싶지 않다면 동의 화면을 게시 상태로 올리거나 학교 Workspace 내부 앱으로 만드세요. 연결이 끊기면 관리 화면의 연결 점검이 실패로 표시됩니다.

#### 2 계정 연결과 폴더 지정 (운영진 인수인계 순서)

관리 화면에서만 진행합니다. 계정 연결·해제는 **owner 권한**만 가능하고, 일반 관리자(manager)는 이미 연결된 Drive를 폼에서 고르기만 합니다.

1. `관리 → 저장소 · Google Drive`로 들어갑니다.
2. 연결 이름(예: `2027 운영위원장 Drive`)을 적고 `새 Google 계정 연결`을 누른 뒤, 본인 Google 계정으로 동의합니다. refresh token은 서버가 암호화해 DB에 저장하며, 화면·API 응답에는 나오지 않습니다.
3. 기존 폴더를 계속 쓰는 경우: 이전 담당자가 새 계정을 그 폴더의 **편집자**로 공유한 뒤, `연결 점검`을 누릅니다. 접근이 안 되면 "현재 연결된 Google 계정은 기존 루트 폴더에 접근할 수 없습니다"가 표시되고, 그 상태에서는 다른 폴더로 조용히 업로드하지 않습니다.
4. 새로 시작하는 경우: `새 루트 폴더 만들기`에 이름을 적고 `구조 미리보기`로 확인한 뒤 `확인 후 생성`을 누릅니다.
5. `테스트 파일 업로드`를 눌러 `_DAH_INTEGRATION_TEST` 폴더에 파일이 들어오는지 확인합니다. 테스트 파일은 자동으로 지우지 않습니다.
6. 이전 담당자의 연결은 `연결 해제`로 정리합니다. 저장된 토큰만 폐기되고 **Drive 안의 파일과 폴더는 삭제되지 않습니다.**

#### 3 폼에서 파일 질문 설정하기

1. `관리 → 행사 설정`에서 폼을 열고 `파일` 질문을 추가합니다.
2. 질문 카드 안에서 `저장 위치`를 고릅니다. 웹에 바로 쓸 이미지는 `Vercel Blob`, 인쇄용·원본은 `Google Drive`입니다.
3. Drive를 고르면 연결 프로필, 폴더 경로 규칙, 마지막 폴더 이름, 공개 범위, 학기, 과목 선택 질문을 지정합니다. 카드 아래에 **예상 저장 경로**가 실시간으로 표시됩니다.
4. `개설 과목 불러오기`를 누르면 `관리 → 교과목`의 학기별 개설 과목을 과목 선택 질문의 보기로 채웁니다. 과목 목록을 손으로 적지 않습니다.
5. `폴더 구조 미리보기`로 없는 폴더를 확인하고, `누락 폴더 준비`로 미리 만듭니다. 여러 번 눌러도 같은 폴더를 재사용합니다.
6. 저장하고 공개합니다. Drive 설정이 덜 된 폼은 공개 저장이 막히고, 무엇이 빠졌는지("연결된 Drive 계정이 없습니다", "2026-2 개설 과목이 없습니다" 등) 목록으로 표시됩니다.

제출자 화면에서는 과목을 먼저 고르지 않으면 원본 파일 업로드 버튼이 잠깁니다. 파일을 올린 뒤에는 과목을 바꿀 수 없고, 바꾸려면 올린 파일을 지우고 다시 올립니다. 이미 제출한 뒤라면 운영진이 Drive에서 파일을 옮깁니다.

#### 4 업로드 기록과 미연결 업로드

업로드는 폼 제출 전에 일어나므로, 서버는 모든 업로드를 `pending`으로 기록하고 제출이 완료되면 `attached`로 바꿉니다. 제출로 이어지지 않은 파일은 `관리 → 저장소 · Google Drive`의 **미연결 업로드**에 남습니다. 자동으로 지우지 않으며, owner가 `기록만 삭제` 또는 `파일까지 휴지통`을 직접 눌러야 지워집니다.

같은 파일을 다시 올리면 서버가 같은 업로드로 인식해 Drive에 중복 파일을 만들지 않습니다. Google API가 일시적으로 429·5xx를 돌려주면 지수 백오프로 재시도합니다.

#### 5 공유 범위

기본 공유 범위는 **제한됨**입니다. 학생 개인정보와 원본 파일은 이 기본값을 유지하세요. 공개 전시 페이지에서 파일을 직접 보여줄 때만 해당 파일 질문의 공개 범위를 `링크가 있는 사용자에게 보기 허용`으로 바꿉니다.

제출자에게는 Drive 권한이 필요하지 않습니다. 파일은 브라우저 → API 서버 → (서버가 보관한 연결 계정의 토큰으로) Drive API 순서로 올라가므로, 폴더를 제한됨으로 두어도 누구나 제출할 수 있습니다.

학교 Google Workspace의 **공유 드라이브**를 쓰는 경우에는 서비스 계정도 사용할 수 있습니다. 서비스 계정을 공유 드라이브 구성원으로 추가하고 `GOOGLE_DRIVE_AUTH_MODE=service-account`, `GOOGLE_DRIVE_SERVICE_ACCOUNT_JSON`을 설정합니다. 개인 Gmail의 `내 드라이브`에는 서비스 계정 모드를 쓰지 않습니다(서비스 계정에는 자체 저장용량이 없습니다).

## 공동 작업과 인수인계

- 학교 GitHub 조직의 저장소 접근 권한을 받은 구성원은 변경사항을 올릴 수 있습니다.
- 작은 수정은 바로 반영할 수 있지만, 구조 변경·DB 변경·배포 설정 변경은 Pull Request 또는 담당자 검토를 권장합니다.
- 작업 전후에는 사이트의 로그인, 주요 목록·상세 페이지, 이미지·첨부파일, 관리자 저장 기능을 확인합니다.
- 담당자가 바뀔 때는 GitHub, Vercel, Render, Neon, Vercel Blob, Google Search Console, Google Analytics의 학교 계정 접근 권한을 함께 인계합니다.
- 개인 계정에만 권한이나 비밀값이 남지 않도록 학교 계정·조직을 기준으로 운영합니다.
