# 한림대학교 디지털인문예술전공 웹사이트

한림대학교 디지털인문예술전공(DAH)의 공식 웹사이트를 관리하는 저장소입니다. 전공을 처음 찾는 예비 학생과 재학생에게는 전공의 정보와 활동을 안내하고, 교수님·운영위원회·향후 인수인계받는 학생 관리자에게는 콘텐츠를 지속해서 운영할 수 있는 기반을 제공합니다.

사이트 주소: [dah-hallym.vercel.app](https://dah-hallym.vercel.app)

## 이 사이트가 하는 일

- 전공 소개, 연혁, 교수진·멘토, CI를 안내합니다.
- 교육과정, 교과목, 코드쉐어링, 나노디그리 등 학사 정보를 제공합니다.
- 공지사항과 자료실을 통해 학사·행사 정보를 전달합니다.
- 프로젝트 전시회, 공모전, 특강, 동아리, 학생 성과, 쇼케이스, 포트폴리오, 취업 현황을 아카이브합니다.
- 전시 접수와 행사 신청을 온라인으로 받고, 관리자는 결과와 콘텐츠를 한곳에서 관리합니다.
- 한국어·영어 화면을 지원합니다. 영문 원고가 등록된 콘텐츠는 영어 화면에서 함께 제공합니다.

## 누가 어떻게 사용하나요?

| 사용자 | 주로 하는 일 |
| --- | --- |
| 방문자·예비 학생 | 전공·교육과정·활동·공지 확인 |
| 재학생 | 전시·공모전·특강·자료실 확인, 전시 및 행사 접수 |
| 교수님 | 공개된 전공·학사·학생 활동 정보 확인 및 관리자에게 수정 요청 |
| 관리자·운영위원회 | 로그인 후 각 페이지의 `편집` 또는 관리자 대시보드에서 콘텐츠 관리 |
| 향후 인수인계자 | 이 문서와 관리자 화면을 기준으로 운영 환경과 배포 흐름 파악 |

## 운영 원칙

1. **콘텐츠는 관리자 화면에서 관리합니다.** 공지, 전시, 공모전, 특강 등 일상적인 내용 수정은 코드를 고치지 않아도 됩니다.
2. **코드는 변경 전 최신 상태를 먼저 받습니다.** 여러 사람이 동시에 작업하므로 작업 시작 전 `git pull`을 권장합니다.
3. **비밀값은 저장소에 올리지 않습니다.** 데이터베이스 주소, 로그인 비밀키, 파일 저장소 토큰, 메일·Google 설정값은 환경변수 관리 화면에만 보관합니다.
4. **운영 사이트를 먼저 보호합니다.** 큰 화면 개편이나 기능 변경은 로컬 또는 미리보기 배포에서 확인한 뒤 운영 배포로 반영합니다.

## 시스템 구성

| 영역 | 사용 서비스 | 역할 |
| --- | --- | --- |
| 사용자 화면·관리자 화면 | React + Vite | 웹사이트와 CMS 화면 |
| API 서버 | Node.js + Express, Render | 로그인, 권한, 콘텐츠·접수 처리 |
| 데이터베이스 | Neon PostgreSQL | 사용자, 콘텐츠, 접수, 공개 상태 저장 |
| 이미지·첨부파일 | Vercel Blob / Google Drive | 일반 콘텐츠는 Blob, 행사 폼의 지정 파일은 폼별 Drive 폴더 |
| 프론트엔드 배포 | Vercel | 공개 웹사이트 배포 |
| 검색·방문 분석 | Google Search Console, Google Analytics | 색인 현황과 방문 흐름 확인 |

## 저장소 구조

```text
client/                 공개 웹사이트와 관리자 대시보드
  src/pages/            각 공개·관리자 페이지
  src/components/       공통 UI, 레이아웃, 편집 도구
  src/data/             기본 안내 문구와 정적 데이터
  public/               파비콘, 로고, robots.txt, sitemap.xml 등 공개 파일

server/                 API 서버
  src/                  인증, 권한, DB 연결, 콘텐츠·업로드 API
  scripts/              데이터 마이그레이션·초기화 보조 도구
  test/                 서버 기본 동작 확인
```

`docs/`는 개인 작업 메모·운영 자료를 로컬에서만 보관하는 폴더입니다. 학교 공용 저장소에는 사이트 운영에 필요한 코드와 이 README만 유지합니다.

## 관리자 화면 사용 안내

1. 사이트 우측 상단의 설정 아이콘에서 관리자 로그인을 합니다.
2. 각 공개 페이지의 `편집` 버튼 또는 관리자 대시보드의 메뉴를 엽니다.
3. 수정 후 저장하면 공개 상태 설정에 따라 사이트에 반영됩니다.
4. 전시·공모전·특강처럼 날짜가 있는 콘텐츠는 새 항목으로 남겨 아카이브가 이어지도록 관리합니다.

관리자 계정은 사전에 데이터베이스에 등록된 이메일만 로그인할 수 있습니다. 등록되지 않은 이메일은 새 사용자로 생성되지 않으며 접근이 거부됩니다.

## 로컬에서 실행하기

Node.js의 현재 LTS 버전을 권장합니다. 처음 한 번만 각 폴더에서 패키지를 설치합니다.

```bash
# 1. 프론트엔드
cd client
npm install
npm run dev

# 2. 별도 터미널에서 API 서버
cd server
npm install
npm run dev
```

프론트엔드는 보통 `http://localhost:5173`, API 서버는 `http://localhost:4000`에서 실행됩니다. 실제 데이터베이스나 업로드 기능을 시험하려면 별도의 로컬 환경변수가 필요합니다. 비밀값은 동료에게 메시지나 저장소 파일로 공유하지 말고, 담당자가 안전한 환경변수 관리 화면에서 설정합니다.

## 배포와 환경변수

프론트엔드는 Vercel, API 서버는 Render에서 각각 배포합니다. 코드가 기본 브랜치에 반영되면 연결된 배포 서비스가 새 버전을 만들 수 있습니다.

프론트엔드에서 주로 확인하는 값은 다음과 같습니다.

| 이름 | 의미 |
| --- | --- |
| `VITE_API_URL` | Render API 서버 주소 |
| `VITE_SITE_URL` | 공개 사이트의 대표 주소 |
| `VITE_GA_ID` | Google Analytics 측정 ID. 비어 있어도 사이트 기능에는 영향 없음 |

백엔드의 `DATABASE_URL`, `JWT_SECRET`, `BLOB_READ_WRITE_TOKEN`, 메일·Google OAuth 관련 값은 **프론트엔드 Vercel에 넣지 않습니다.** Render의 서버 환경변수에만 둡니다.

### 행사 파일을 Google Drive에 저장하려면

행사마다 파일이 섞이지 않게, 폼별로 별도 Drive 폴더를 연결할 수 있습니다. 일반 `내 드라이브` 폴더에는 **학교 Google 계정 OAuth**로 업로드합니다. Google 비밀번호를 서버에 저장하지 않으며, 승인 후 발급된 refresh token은 Render 서버 환경변수에만 둡니다.

1. 학교 또는 운영 계정 Drive에 행사별 폴더를 만듭니다. 예: `DAH 운영 / 2026-2 프로젝트 전시 / 제출 파일`.
2. Google Cloud Console에서 Drive API와 OAuth 동의 화면을 설정하고 웹 애플리케이션 OAuth 클라이언트를 만듭니다.
3. 파일을 보관할 Google 계정으로 Google Drive 접근을 승인해 refresh token을 발급합니다. 2026-2 전시회는 현호 개인 Drive를 사용합니다.
4. `GOOGLE_DRIVE_CLIENT_ID`, `GOOGLE_DRIVE_CLIENT_SECRET`, `GOOGLE_DRIVE_REFRESH_TOKEN`을 Render 서버 환경변수에만 넣습니다. Vercel이나 GitHub에는 넣지 않습니다.
5. 관리자 → `폼` → 해당 폼 `편집`에서 `Google Drive 파일 업로드`를 켜고, 폴더 URL 또는 ID를 붙여 넣은 뒤 저장합니다.
6. 폼에 `파일` 질문을 추가합니다. 제출자는 Google Drive 아이콘이 있는 `Google Drive로 업로드` 버튼을 보며, 업로드된 파일 URL은 그 폼의 응답 시트에 저장됩니다.

학교 Google Workspace의 **공유 드라이브**를 사용하는 경우에는 서비스 계정도 사용할 수 있습니다. 이때 서비스 계정을 공유 드라이브 구성원으로 추가하고 `GOOGLE_DRIVE_AUTH_MODE=service-account`, `GOOGLE_DRIVE_SERVICE_ACCOUNT_JSON`을 설정합니다. 개인 Gmail의 `내 드라이브`에는 서비스 계정 모드를 사용하지 않습니다.

기본 공유 범위는 **제한됨**입니다. 제출물 URL을 외부 전시 페이지에서 직접 보여줄 필요가 있을 때만, 해당 폼의 공유 범위를 `링크가 있는 사용자에게 보기 허용`으로 바꿉니다. 학생의 개인정보·원본 파일은 기본값을 유지하세요.

## 공동 작업과 인수인계

- 학교 GitHub 조직의 저장소 접근 권한을 받은 구성원은 변경사항을 올릴 수 있습니다.
- 작은 수정은 바로 반영할 수 있지만, 구조 변경·DB 변경·배포 설정 변경은 Pull Request 또는 담당자 검토를 권장합니다.
- 작업 전후에는 사이트의 로그인, 주요 목록·상세 페이지, 이미지·첨부파일, 관리자 저장 기능을 확인합니다.
- 담당자가 바뀔 때는 GitHub, Vercel, Render, Neon, Vercel Blob, Google Search Console, Google Analytics의 학교 계정 접근 권한을 함께 인계합니다.
- 개인 계정에만 권한이나 비밀값이 남지 않도록 학교 계정·조직을 기준으로 운영합니다.

## 문제가 생겼을 때

| 증상 | 먼저 확인할 곳 |
| --- | --- |
| 화면은 열리지만 목록·로그인이 안 됨 | Render API 배포 상태와 `VITE_API_URL` |
| 이미지·포스터·첨부파일이 안 보임 | Vercel Blob 연결과 Render의 파일 저장소 설정 |
| 관리자 로그인이 거부됨 | 데이터베이스에 해당 이메일과 권한이 등록됐는지 |
| 새 수정이 사이트에 안 보임 | GitHub 반영 여부, Vercel 최신 배포, 브라우저 강력 새로고침 |
| 검색 결과·파비콘이 예전 모습임 | Search Console 색인 상태와 브라우저/Google 캐시. 반영까지 시간이 걸릴 수 있음 |

## 보안 안내

이 저장소는 공개 또는 공동 관리될 수 있습니다. 비밀번호, 토큰, 데이터베이스 연결 주소, 학생 개인정보가 담긴 파일을 커밋하거나 Issue·README에 적지 마세요. 노출이 의심되는 비밀값은 즉시 해당 서비스에서 교체하고, 필요하면 운영 담당자에게 알립니다.
